# Frontend design

Start from the product's purpose and the existing visual language. Inspect nearby screens and components before making design decisions.

- Establish a small, consistent system for typography, color, spacing, borders, radii, and elevation. Reuse existing tokens; introduce a few cohesive tokens only when needed.
- Give each screen a clear visual hierarchy and a focal point. Prefer purposeful composition and readable content widths over a collection of generic cards.
- Make layouts work from narrow mobile widths through desktop. Use flexible sizing, sensible breakpoints, and avoid horizontal overflow.
- Make buttons, forms, navigation, and status messages visually distinct and consistent. Include loading, empty, error, and success states where the flow needs them.
- Favor restrained, meaningful decoration. Avoid defaulting to gradients, excessive shadows, arbitrary icons, or decorative motion without a product reason.
- Use existing image and icon libraries where available. Do not invent new external assets or dependencies without need.

Check the result at mobile and desktop widths and verify that long text, errors, and empty states still fit.
